# 制作流程

先把需求转成可检查的交付目标: 视频用途, 观众, 时长, 横竖比例, 语言, 是否配音与配乐, 用户素材和必须保留的信息.  简单需求直接采用合理默认值并说明关键选择, 不把每个创作细节都变成确认门.

| 任务 | 重点 |
| --- | --- |
| 解说与知识故事 | 信息顺序, 旁白, 图解与镜头承接 |
| 产品与品牌短片 | 核心卖点, 视觉方向, 标题与收尾 |
| 生成式视频叙事 | 连贯角色与环境, 实际动态画面, 剪辑节奏 |
| 用户素材剪辑 | 源片段入出点, 原声, 连贯性与目标比例 |
| 配音图像叙事 | 分场景配音, 实测时长, 图像与文字信息 |

写 production-plan.json 记录 brief, 场景列表和需要的素材.  每个场景明确传达什么, 为什么需要该镜头, 对应哪段旁白.  保留 OpenMontage 的交付承诺: 用户要求真实动态镜头时, 不用静态图片轮播代替后称为同等成片.  用户要动态图形时使用 Remotion 或自写本地动画, 不把静态卡片拼接描述为动画制作完成.

先复用用户附件, 再按场景生成必要素材.  保持角色, 调色, 画幅和音色一致.  配音先取得真实音频并测量, 视觉素材再按实际时长布局.  生成失败时保存素材清单和已完成文件, 报告具体原因; 不用另一场景的音频或空文件补位.

FFmpeg 适合真实视频拼接, 图片叙事, 原声保留和配音配乐混合.  它不提供本版模板动画或自动字幕.  导入素材后, 写项目中的 timeline.json:

```json
{
  "width": 1280,
  "height": 720,
  "fps": 30,
  "clips": [
    {"asset":"opening","duration":4},
    {"asset":"scene-two","duration":6,"sourceStart":0,"mute":true}
  ],
  "audio": [
    {"asset":"voice-one","start":0,"volume":1},
    {"asset":"voice-two","start":4,"volume":1},
    {"asset":"music","start":0,"volume":0.12,"loop":true}
  ]
}
```

所有 asset 都必须在 assets.json 中登记.  clips 按顺序拼接, 默认完整保留画面并补黑边, 不擅自裁掉内容.  视频片段不得超出源文件时长; 图片不能设置 sourceStart.  输出宽高为正偶数, fps 为正整数.  audio.start 是成片时间, 单位秒; volume 范围 0-2, loop 只在明确需要循环时使用.  不通过循环配音伪造更长的语音内容.

成片写入新 MP4, 不覆盖已有文件.  render 会验证资产哈希, 合成并核对视频及音频各自时长, 帧率, 尺寸和完整解码, 提取首中末帧并报告音量.  这些只是技术指标.  实际复核画面内容, 可读性, 字幕和语音后才能说明内容通过.  需要有声却实际静音, 音频截断, 中文缺字或重要素材丢失时不能交付为通过.

原版纯本地创作辅助库保留于 lib, 可通过 skill 根目录加入 Python 导入路径使用.  shot_prompt_builder 帮助构造镜头提示词, slideshow_risk 和 variation_checker 帮助检查重复与静态卡片风险, media_profiles 提供常用画幅, verify_scene_pacing 用于终端演示与旁白时序.  分数是创作参考, 不能替代实际渲染或视觉检查.
